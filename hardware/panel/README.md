# Букифон — схемы PANEL-1 / DECK-PAD / DECK-KEYS

Открытые схемы (KiCad 10, формат `.kicad_sch` версии 20250114) трёх плат панели
синтезатора-геймпада Букифон. Лицензия: **CERN-OHL-S-2.0** (см. `spec/00-vision.md` §5).

Лист схемы: PANEL-1 — A1, DECK-PAD — A1, DECK-KEYS — A0 (KiCad paper size).

## 3. Архитектурные решения, важные для чтения схем

- **Соединения заданы именами цепей** (метка на 2.54 мм выводе каждого пина).
  Это стандартный способ рисовать большие матричные/шинные схемы и единственный
  практичный при 42 клавишах и 48 битах сдвиговых регистров: схема читается по
  именам цепей, а полная карта соединений — в `matrix-tables.md` (сверена с netlist).
  Разводка «проводами» была бы нечитаемой и не несёт дополнительной информации.
- **Питание**: символы `power:+3V3`, `power:GND`, `power:+5V` + `PWR_FLAG` (в начале
  каждой схемы). `PWR_FLAG` нужен ERC, чтобы обозначить, что питание приходит по
  шлейфу, а не вырабатывается на плате.
- **Символы производных библиотечных элементов** (`74HC165`, `1N4148`, `SK6812MINI-E`,
  `MCP23017x-x-SP`, `2N7002`) взяты как базовые аналоги (`74LS165`, `1N4001`,
  `SK6812`, `MCP23017x-x-SO`, `Q_NMOS_GSD`) с правильным значением/корпусом: иначе
  ERC выдаёт `lib_symbol_mismatch` на каждый экземпляр. Электрически и по цоколёвке
  они идентичны; важно для BOM — там стоит правильное изделие.
- **74HC165**: каскад `U1.Q7 → U2.DS → … → U6.Q7 = HC_QH`; бит 0 — `U1.D0`,
  бит 47 — `U6.D7` (первым по MISO читается `U6.H`). Свободные биты 28…47
  посажены на GND; `~Q7` не используются (no-connect), `~CE` = GND.
- **WS2812B-2020 / SK6812MINI-E**: цепочка PANEL-1 (9 LED) питается от **+5 В**
  (`spec/20-electronics.md` §2/§3/§6.1), данные `LED_DATA` (GP7, 3.3 В) идут через
  буфер **U7 74HCT1G125** (VCC = +5 В, TTL-совместимый вход) → R300 330 Ω → `LED_IN`
  → LED_ENC1…8 → LED_STATUS → `LED_OUT` (pin 7 J-DECK) → цепочка деки (18 или 42 LED).
  100 нФ на каждый светодиод, ёмкости — на +5 В. Цепочки дек питаются тем же +5 В
  через **pin 16 IDC-16** (`spec/20-electronics.md` §6.2: pin 15 = FSR, pin 16 = +5V):
  `LED_IN` приходит с панели уже с уровнем 5 В, т.е. уровни данных и питания
  светодиодов совпадают (даташитные ограничения соблюдены).
- **Энкодеры**: каждая фаза — 10 кΩ к +3V3 (это и есть R фильтра) + 100 нФ на GND
  ⇒ 16 RC-цепочек; кнопка энкодера — отдельный 10 кΩ pull-up (8 шт.).
- **Слайдеры/FSR**: RC 1 кΩ + 100 нФ стоят на PANEL-1, перед MCP3208 (CH0/CH1 для
  SL1/SL2, CH6 для FSR), как в `spec/20-electronics.md` §6.2.
- **I2C**: на PANEL-1 добавлены 4.7 кΩ подтяжки для сегмента шлейфа деки (на CORE-1
  свои 4.7 кΩ) — эффективно 2.35 кΩ, допустимо для 100 кГц/400 кГц.
- **Матрицы пэдов/клавиш**: столбцы читаются с внешними 10 кΩ подтяжками
  (`R21..R26`/`R21..R27`): встроенные 100 кΩ MCP23017 слабоваты для шлейфа 10 см.
  Строки — выходы MCP23017, активный низкий; диоды 1N4148 в деке клавиш
  (анод = клавиша, катод = столбец).

## 4. Ограничения и открытые вопросы

1. **Все LED-цепочки на +5 В** (дефект «WS2812 при 3.3 В» закрыт). Панель: GP7 (3.3 В) →
   буфер **U7 74HCT1G125** (VCC = +5 В, TTL-совместимый вход) → R300 330 Ω → LED_ENC1…8 →
   LED_STATUS → `LED_OUT`; 9×WS2812B-2020 и их 100 нФ — на +5 В. Деки: +5 В приходит
   через **pin 16 IDC-16** (`spec/20-electronics.md` §6.2), 18×WS2812B-2020 /
   42×SK6812MINI-E и их 100 нФ — на +5 В; `LED_IN` с панели уже имеет уровень 5 В,
   поэтому уровни питания светодиодов и данных совпадают. Питание +5 В на панели —
   J-CORE pin 21, на деках — pin 16 J-DECK; на каждой плате стоит `PWR_FLAG` (+5V).
2. **DECK_ID** — точные значения по `spec/20-electronics.md` §6.2: DECK-PAD = 33k/3.3k
   ⇒ **0.30 В**, DECK-KEYS = 3.3k/33k ⇒ **3.00 В** (допуск ±0.15 В). Проверяется
   `verify_netlist.py` по номиналам из netlist.
3. **`DECK_INT` → GP28** — закреплено в `spec/20-electronics.md` §2 (GP28 = DECK_INT,
   прерывание MCP23017 деки; при этом GATE1 = GP22, GATE2 = GP26, DECK_ID = GP27).
   Цепь идёт: pin 5 J-DECK → pin 19 J-CORE → GP28 CORE-1; подписано в схемах и в
   `matrix-tables.md` §2.6.
4. **Kailh Choc hot-swap**: посадочного места в стоковых библиотеках KiCad нет,
   поле Footprint у `KEYn` пустое (иначе ERC ругается на несуществующую библиотеку).
   Нужно нарисовать footprint гнезда (CPG1350) — это задача этапа PCB.
5. **IDC-32 (2×16)**: в стоковой библиотеке `Connector_IDC` есть 2×08, но нет 2×16,
   поэтому в схеме стоит `PinHeader_2x16_P2.54mm_Vertical`; при заказе платы
   заменить на IDC-бокс 2×16 (или оставить штыревой разъём + шлейф).
6. **Нумерация выводов светодиодов** (DIN/DOUT/VDD/VSS) взята из символов библиотеки
   KiCad 10 (`LED:WS2812B-2020`, `LED:SK6812`), а не из даташита. Перед разводкой
   платы сверить с даташитом конкретного светодиода (для SK6812MINI-E вывод 1 = VSS
   в библиотеке KiCad).
7. **Только схема**: `.kicad_pcb` (размещение/трассировка), 3D-модели и проверка
   технологичности в этот объём не входят. Схемы дают полный netlist для импорта.
8. **Монтаж**: `PANEL-1` — 1.6 мм, EC11 и тактовые кнопки THT, логика SMD (SOIC/DIP по
   BOM); TP-точки не добавлялись (не требуются спецификацией).
9. **Питание LED-цепочек**: все цепочки на +5 В (9 LED панели + 18/42 LED деки;
   до 51 LED при DECK-KEYS). При 10 мА на LED это ≤ 510 мА по +5 В (бюджет +5 В —
   до 0.8 А, `spec/20-electronics.md` §3), +3V3 разгружен до экрана и логики.
   Ограничение яркости в прошивке (`spec/40-firmware.md`) всё равно обязательно:
   средний ток LED держать ≤ 10 мА, чтобы не перегревать деки и шлейф.

## 6. Как читать схемы

1. Верхний уровень — блоки с текстовыми комментариями (энкодеры, регистры, экран,
   LED, разъёмы). Внутри блока — компоненты с метками цепей.
2. Имя цепи — то, что читает прошивка: например `ENC3_PUSH`, `ROW2`, `COL5`,
   `MUX_S1`, `LED_CH12`, `SL1_RAW`.
3. Полная таблица «координата панели ↔ цепь ↔ бит/канал» — `matrix-tables.md`;
   она автоматически сверяется с netlist при каждом `./tools/build.sh`.
4. Если меняете схему — правьте `tools/gen.py` (данные в начале файла) и запускайте
   `./tools/build.sh`: перегенерируются схемы, таблицы, BOM, ERC и проверка.

## 7. BOM

`BOM-panel.csv` (разделитель `;`) — три платы, строки сгруппированы по
номинал+корпус, есть итоги по позициям. Колонка «Артикул (предложение)» — типовые
MPN для закупки (проверять наличие/цену при заказе; сводный BOM проекта с ценами —
`../docs/BOM.md`, задача task-6). Для деков BOM считается на один вариант: PANEL-1
общая для обоих деков, LED-цепочки отличаются (9 + 18 либо 9 + 42).
