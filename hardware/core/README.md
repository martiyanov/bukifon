# CORE-1 — плата ядра Букифон (открытая схема)

**Ревизия:** 1.0 (по `spec/20-electronics.md` v1.1 — 6 CV-выходов, 2 × MCP4728)
**Лицензия:** CERN-OHL-S-2.0 (аппаратура), GPL-3.0-or-later (прошивка)
**Габарит:** 200 × 108 × 1.6 мм (разводка платы — следующий этап, см. «Ограничения»)

Схема сгенерирована скриптом `gen_core_sch.py` в нативный формат KiCad 10
(S-expression, `version 20250114`). Это осознанное решение: `kicad-cli sch upgrade`
в KiCad 10.0.4 **не импортирует** legacy EESchema v5 (`$Comp`/`$Sheet`) — он умеет
только пересохранять S-expression. Генератор сразу пишет `.kicad_sch`, а затем сам
запускает `kicad-cli` для ERC и экспортов.

## 1. Что в схеме

| Блок | Состав |
|---|---|
| **Питание** | J-DC (J14) → SW1 → F1 2A → TVS SMAJ15A → SS34; MP1584 → +5.1 В; AP2112K-3.3 → +3V3; MC34063 → −12 В; ферриты 600 Ом на +12/−12/+5/+3V3/Vref; 1000 мкФ, 100 мкФ на рельсах; «звезда» AGND/DGND/PGND на net-tie NT1/NT2 |
| **Pico** | A1 `RaspberryPi_Pico`, 40 контактов (кастеляция SMD), RESET (SW2 + 10k + 100nF), SWD (J16 + площадки J13), VSYS через SS34 (D4), развязка 100nF/10uF |
| **Аудио** | PCM5102A (I2S от PIO GP16/17/18) + charge pump (CAPP/CAPM, VNEG, LDOO) → 10 мкФ → TL074 инвертирующий сумматор (Rf 22k; DAC через 10k, 3 × AUD_OUT порта через 22k + защита 1k/BAT54S/100pF) → сдвоенный MASTER VOL 10k → TL072 ×2 буфер → 100 Ом → LINE OUT / PHONES. AUD_IN = DAC L / 2 через буфер, 1k |
| **CV** | **2 × MCP4728**: U4 (0x60) CH A–D → TL074 ×4.9 → CV1…CV4 на шину P1/P2/P3; U16 (0x61) CH A/B → TL074 ×4.9 → CV5/CV6 на джеки CV OUT 1/2. На каждый выход 1k + BAT54S |
| **АЦП** | MCP3208: CH0/1 = SL1/SL2, CH2/3 = CV IN 1/2 (джеки, −10…+10 В → 0…3.3 В через инвертирующий аттенюатор 100k/16.5k со сдвигом 1.65 В), CH4/CH5 = резерв (притянуты к AGND), CH6 = FSR, CH7 = SYS_MON (+5 В, делитель 12k/18k) |
| **Прочее** | 24C32 (калибровка, адрес 0x57), MIDI IN 6N137 / MIDI OUT 74HCT125, GATE1/2 на 2N7000 (open-drain, pull-up 4.7k на +5V_B), ключ подсветки LCD на 2N7002 (Q3), LED_DATA с 330R |
| **Разъёмы** | P1/P2/P3 — IDC-26 (шина Букифон), J15 — IDC-32 (PANEL-1), TB1/TB2 — клеммники 3.81 мм для панельных джеков, J16 — SWD 1×3 |

Карта пинов Pico, карта шины, клеммников и джеков — в
`wiring-jacks.md` (сгенерирована из той же таблицы, что и схема).

## 3. Как открыть и перегенерировать

```bash
# открыть в KiCad 10
open -a KiCad CORE-1.kicad_pro

# перегенерировать всё (схема + ERC + экспорты + BOM + доки)
cd hardware/core
/opt/homebrew/bin/python3 gen_core_sch.py

# только схема (без экспортов)
/opt/homebrew/bin/python3 gen_core_sch.py --no-export

# ERC вручную
/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli sch erc --severity-all \
    --format report -o erc/erc.rpt CORE-1.kicad_sch
```

Проверка электрической корректности дублируется автоматической сверкой netlist с
таблицей соединений генератора (число цепей, состав узлов, отсутствие «чужих» пинов).
Проверено также, что нет геометрических замыканий: провода разных цепей не
пересекаются и не накладываются.

## 5. Решения и отклонения от буквы спецификации (важно!)

1. **CV-контракт v1.1 реализован**: 6 CV-выходов. MCP4728 #1 (U4, 0x60) — CV1…CV4 на
   шину, MCP4728 #2 (U16, 0x61) — CV5/CV6 на джеки CV OUT 1/2. У MCP4728 в MSOP-10
   **нет адресных выводов**: адрес задаётся исполнением (адресные биты — в EEPROM,
   datasheet Microchip DS22187). Поэтому в BOM заказаны штатные варианты
   **MCP4728A0-E/UN** (0x60) и **MCP4728A1-E/UN** (0x61); без варианта A0/A1
   потребуется программатор для смены адреса. MPN проставлены в BOM.
2. **CV IN ±10 В**: в §5 буквально указано «100 kΩ → 47 kΩ → BAT54S → RC». Прямой
   делитель 100k/47k не измеряет отрицательную полуволну (0…3.2 В только для
   положительной). Реализован корректный вариант: инвертирующий аттенюатор
   100k / 16.5k со сдвигом +1.65 В (47k/47k от +3V3 через буфер TL074), затем
   BAT54S, 1k/100nF и MCP3208 CH2/CH3. Формула: `Vadc = 1.65 − 0.165·Vin`.
3. **Земли**: AGND, DGND, PGND — три отдельные цепи, соединённые в одной точке
   net-tie NT1/NT2 (footprint `NetTie:NetTie-2_SMD_Pad0.5mm`). Netlist по определению
   оставляет их раздельными — «звезда» делается на PCB.
4. **Pico 3V3 не подключён** (no-connect): Pico питается от VSYS (+5 В через SS34),
   его внутренний LDO остаётся только для Pico (как в §2). Внешний +3V3 для логики и
   панели даёт AP2112K. Это исключает параллельную работу двух регуляторов.
5. **Карта пинов Pico** — по окончательной редакции §2: GP22 = GATE1, GP26 = GATE2
   (пин 31), GP27 = DECK_ID (ADC1, пин 32), GP28 = DECK_INT (пин 34, MCP23017 INTA
   деки через J15 pin 19). Расхождений с §2 в схеме нет.
   На J15 (IDC-32): pin 19 = `DECK_INT`, pin 20 = `LED_DATA`; SYS_MON читается только
   MCP3208 CH7 (Pico ADC0 на GP26 больше не используется).
6. **MCP4728 #2**: CH C/D не используются (выведены no-connect, как разрешил Lead).
7. **MCP3208 CH4/CH5** — резерв: притянуты к AGND (не висят в воздухе).
8. **24C32** — адрес 0x57 (A2/A1/A0 = 1), чтобы не конфликтовать с EEPROM модулей
   0x50 + номер порта (§7). Калибровочные данные ядра — по 0x57.
9. **Коэффициент CV-буферов**: 39k/10k = 4.9 (0…10.04 В) вместо точных 4.883
   (E96 38.3k). Рекомендуется калибровка по EEPROM; при желании заменить Rf на 38.3k.
10. **Подсветка**: ключ 2N7002 (Q3) стоит на CORE-1 (чек-лист §11), при этом §6.1
    описывает такой же ключ на PANEL-1. Заполнять только один вариант — на PANEL-1
    Q3 не ставить (либо наоборот). Отмечено в BOM.
11. **Аудиобуфер AUD_IN** использует свободную секцию TL074 (U10 unit D); TL072 (U11)
    — два буфера LINE/PHONES. Резервные секции TL074 заземлены (unit 4 у U10, U13, U17).
12. **Питание −12 В**: MC34063 в инвертирующем включении с «плавающей» землёй
    (pin 4 = −12 В), делитель ОС 33k/3.9k, Rsc 0.33, Ct 1.5nF, L 220 мкГн, D3 SS34.
    Номиналы — стартовые; при наладке проверить частоту/пульсации.
13. **AUD-сумматор**: Rf = 22k, входы DAC 10k, входы портов 22k. PCM5102A 2.1 В rms →
    ~4.6 В rms на выходе сумматора (без клиппинга при ±12 В), MASTER VOL — после.
14. **Обозначения**: KiCad требует стандартных позиционных обозначений, поэтому
    J-DC → J14, J-PANEL → J15, HDR-EXT → J16, Rsc → R74, Ct → C59, Rfb1/Rfb2 →
    R75/R76. Соответствие — в столбце «Примечание» BOM (`spec: J-DC` и т.п.).
15. **Разъёмы джеков**: панельные джеки в схеме показаны символами (J1…J12) и
    подключены к клеммникам TB1/TB2; на CORE-1 они не паяются (footprint пустой,
    BOM помечает «не на CORE-1»).
16. **GND на шине**: §7 называет все нечётные «GND»-пины одинаково; в схеме они
    разделены по назначению возвратов: пины 2/4/6/8 — `DGND` (питание/цифра),
    пины 10…16 — `AGND` (CV/аудио). Все три земли всё равно соединяются в одной
    точке (NT1/NT2), так что для модуля это один провод GND.

## 6. Ограничения (что НЕ сделано)

- **Нет PCB** (`.kicad_pcb`) и DRC: по приоритету задачи плата — следующий этап.
  Все footprint-строки в схеме — черновые (проверяются только именами библиотек;
  для IDC-32 footprint пуст — в библиотеках KiCad нет `2x16` IDC).
- **Нет библиотеки футпринтов проекта** (`Букифон.pretty`) — посадочные места
  MP1584-модуля и Pico SWD-площадок заданы пустыми.
- **Нет цен** в BOM: артикулы `PM-CORE-NNN` — внутренние коды. MPN указаны только
  для двух MCP4728 (MCP4728A0-E/UN и MCP4728A1-E/UN, т.к. от них зависит I2C-адрес);
  для остальных позиций MPN/поставщик не выдумывались.
- **Не проверены на макете**: номиналы MC34063, уровень −12 В, температурные
  режимы. Это схемотехнический проект, а не отлаженный образец.
- ERC не проверяет целостность питания/тепловые режимы и корректность номиналов —
  только электрические правила соединений.
