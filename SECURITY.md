# Безопасность и приватность

## Что в репозитории НЕ должно появляться

- токены, пароли, API-ключи, приватные ключи, `.env`, конфиги с секретами;
- фотографии с **EXIF/GPS** (геолокация), серийные номера устройств;
- PDF/сканы с трекингом, IP-адресами и персональными данными;
- абсолютные пути вида `/Users/<имя>/...` в текстовых файлах;
- чужие персональные данные (адреса, телефоны, e-mail без согласия).

## Правила

1. Фото для документации — только после очистки метаданных:
   `sips -s format jpeg --deleteProperty exif image.jpg --out clean.jpg` или PIL-пересохранение.
2. Скачанные datasheet'ы **не коммитить** — вместо файлов давать ссылку на производителя
   (`refs/datasheets/` в `.gitignore`).
3. Секреты — только через переменные окружения/локальные конфиги, никогда в git.
4. Перед пушем: `bash tools/security_scan.sh` (входит в `tools/check_all.sh`).

## Если секрет попал в историю

1. Немедленно **отозвать/сменить** секрет (токен, ключ, пароль) — история не важна, важен отзыв.
2. Вычистить историю: `git filter-repo --invert-paths --path <файл>` (+ `--replace-text`),
   затем force-push всех веток и тегов.
3. Уведомить участников; старые коммиты могут быть доступны по SHA, пока GitHub не соберёт мусор —
   при необходимости обратиться в поддержку GitHub для purge.

## Сообщить о проблеме

Откройте приватный security advisory в GitHub (Security → Advisories → New draft advisory)
или напишите владельцу репозитория. Не создавайте публичный issue с деталями уязвимости.
