# Ночной план до v1.0-rc (scope freeze)

Источник: консультация GPT/Codex (05.11.2025, `docs/04-consultation-gpt.md`-соседний
документ — полный ответ техлида). Главный вывод: за ночь нельзя получить новую
аппаратную v1.0. Максимум — **интегрированный цифровой прототип**, который запускается,
показывается и проверяет будущие платы.

## Цель к утру (одно предложение)

На компьютере запускается интерфейс **800×480**, 16 энкодеров и 42 клавиши управляют
**4-дорожечным 16-шаговым секвенсором**, события доходят до аудиодвижка; рядом —
проверенные контракты CORE-2/PANEL-2 (pre-freeze) и выбранный корпус **wedge 8°**.

## Пять артефактов (приоритет)

| # | Артефакт | Критерий «готово» |
|---|---|---|
| 1 | Host-прототип 800×480 | один запуск; стабильные 30 fps; ввод → событие → UI/audio; детерминированный сценарий |
| 2 | Вертикальный музыкальный slice | 4 дорожки × 16 шагов, note/mute/BPM, один p-lock, save/load |
| 3 | CORE-2/PANEL-2 architecture pack | ERC без ошибок; таблицы pin/power/bus; нет конфликтов; открытые вопросы перечислены |
| 4 | Корпус v0.5 «wedge 8°» | рендер, боковой профиль, шаблон 1:1; rear ≤63 мм; экран читается |
| 5 | Nightly evidence bundle | README запуска, тесты зелёные, ограничения, «что нельзя заказывать» |

## Что режем (запрет на ночь)

- 3 корпуса → только **8°**; плоский и 12° — сравнительные рендеры, без доводки.
- Полный sampler/granular/ZDF/USB Audio/SD streaming — нет.
- ABI модулей — **experimental v0**, не стабильный.
- PCB-разводка и герберы — нет.
- Полировка BOM/сайта/графики — только после интеграционного демо.
- 8 дорожек не делать: для UI-демо хватит 4; архитектура должна допускать 8.

## Эргономика: wedge 8° (зафиксировано)

| Параметр | Значение |
|---|---|
| Наклон панели | **8° к столу** |
| Передняя кромка | **31–33 мм** |
| Задняя кромка | **60–63 мм** |
| Перепад | 210 × tan 8° ≈ **29.5 мм** |
| Фаска/радиус спереди | R3–R5 |
| Экран относительно панели | **35°** (≈43° к столу), допустимо 30–45° |
| Центр экрана от передней кромки | ≤ **150–170 мм** |
| Частые энкодеры от передней кромки | ≤ **190–210 мм** |

Проверка без печати: картонный профиль (перед 32, зад 62), панель 1:1 сверху, экран
на шарнире 30/35/45°, цилиндры Ø14 вместо ручек; три позы (низко/прямо/стоя); критерии
отказа — кисть задевает энкодеры, дальний ряд требует отрыва локтя, блики, острая кромка.

## Электроника (pre-freeze, DO NOT FABRICATE)

Три обязательные проверки до любых плат:
1. **Pin/resource ownership** — таблица `signal → pin → peripheral → voltage → direction →
   pull → boot state → connector`; автоматическая проверка дублей и boot-состояний.
2. **Power tree** — USB-C/батарея → заряд → 5/3.3/аналоговые рельсы; worst-case ток,
   пусковой ток дисплея/PSRAM/SD/BL, power-path, brownout, запас регуляторов ≥25%.
3. **Audio/CV/USB контракт** — I2S master/частоты, USB HS PHY/ESD, CV IN защита ±12 В,
   CV OUT калибровка, mute при старте, развязка клоков.

## Прошивка: порядок ночи

1. Host simulator + event layer (один поток событий в тестах и UI, воспроизводимый из файла).
2. UI shell 800×480 (status bar, дорожки, параметры, transport; 30 fps).
3. Секвенсорный slice (4×16, BPM, play/stop, note, mute, p-lock).
4. Save/load с version field.
5. Module API v0 + 2 встроенных примера.
6. Hardware adapters/stubs (P4 HAL компилируется или stubbed; основной код без ESP-IDF).
7. Demo/test script: строит паттерн, играет 16 тактов, сверяет журнал событий.

## Module API v0 (черновик, не стабильный)

descriptor (abi_version, struct_size, UUID, name, vendor, kind, flags) → create(host, config) →
prepare(sample_rate, max_block) → reset → process(inputs, outputs, frames ≤64) →
set_param(id, value) → state_size/save_state/load_state → destroy.
В `process()` запрещены: allocation, locks, FS/network, logging, UI-callbacks, неопределённые
циклы. Host меряет worst-case, два превышения подряд → bypass + fault flag.

## Definition of done к утру

- полная чистая сборка; старые host-тесты не сломаны;
- новые тесты: transport, wrap шага, p-lock, save/load, module budget failure;
- нет malloc/locks/FS в audio callback; UI не владеет состоянием секвенсора;
- один непрерывный проход демо: запуск → паттерн → playback → p-lock → save/load;
- nightly report: что работает, что симулируется, что **нельзя заказывать**.
