## P0. Заморозка benchmark workload (1 неделя) — новый первый шаг

Без этого бенчмарк бессмысленен: «insert», ZDF и granular не определены алгоритмически.

- [ ] зафиксировать точные алгоритмы: 8 голосов FM (сколько операторов, oversampling),
      ZDF-фильтр (число итераций), granular stretch (размер гранулы, интерполяция),
      1 insert/track + 2 send + master;
- [ ] зафиксировать длины сэмплов (30 с), формат (16 бит), конфигурацию UAC2 (8×8/24/48);
- [ ] зафиксировать тестовые проекты: «максимум» (8 дорожек + 8 голосов + все FX) и «типичный».

**Выход:** один документ `docs/05-benchmark-workload.md` с точными параметрами; по нему
пишутся тесты.

## P1. Бенчмарк: ESP32-P4 против STM32H743 (2–3 недели)

Заказать: **ESP32-P4** (32 МБ PSRAM) и **Nucleo-H743ZI2**. ESP32-S3 не тестировать на
8×8 UAC2 — он аналитически не проходит (9.2 Мбит/с > FS isochronous). Teensy 4.1 — только
как референс DSP-ядер, не как кандидат.

- [ ] granular random-read PSRAM (линия 64 Б, 8–16 сэмплов) — МБ/с и cache-miss latency;
- [ ] DSP-ядра: FM-голос, ZDF-фильтр, granular, insert — время на блок 64;
- [ ] фреймбуфер 800×480: DSI/PPA (P4) vs LTDC+DMA2D (H743), полная/частичная перерисовка;
- [ ] USB UAC2 8×8/24/48 **вместе** с SD и дисплеем;
- [ ] замер max/min времени аудиоблока (не среднее).

**Критерии выхода:** `max block time ≤ 0.65 мс` при дедлайне 1.333 мс (блок 64 @48 кГц),
0 xruns за 1 час, таблица «платформа × задача → %CPU / МБ/с / fps».

## P2. Вертикальный spike (3–4 недели)

Главный вывод обоих ревью: устройство падает не на изолированном DSP, а когда
**USB + SD + DSI + PSRAM работают одновременно**.

- [ ] одновременно: аудио (8 mono + 8 голосов), запись/чтение SD, перерисовка UI
      (волна/осциллограф), USB UAC2 8×8, сканирование панели;
- [ ] torture-test 24 часа: логировать max block time, xruns, missed UI frames, SD latency;
- [ ] проверить policy: при перегрузке — снижение quality tier (меньше голосов/FX), а не глитч.

**Критерии выхода:** 24-часовой soak без xruns; max block time ≤ 50–55 % дедлайна;
деградация управляемая.

## P3. Требования и cut-list (1 неделя)

- [ ] обновить `spec/90-requirements-registry.md` по результатам P1–P2 (MCU, дорожки,
      голоса, FX, stretch, USB);
- [ ] подписанный cut-list: 8 mono, 1 insert + 2 send, granular stretch с admission control,
      ZDF с фиксированным числом итераций, качество по tiers;
- [ ] привести устаревшие документы (spec/20, spec/40, README, firmware/README) к v0.4;
- [ ] зафиксировать цифровой expansion-интерфейс: TDM/I²S + SPI mailbox (не только
      26-pin аналоговая шина).

**Выход:** design freeze; изменения внесены в спеки; cut-list подписан.

## P4. Аудиоядро и панель на devkit (8–12 недель, параллельно)

Аудио:
- [ ] 8 голосов FM/wavetable + ZDF; 8 mono-дорожек + granular; 1 insert + 2 send;
- [ ] UAC2 по возможностям платформы, MIDI TRS + USB-MIDI, SD-стриминг;
- [ ] 24-часовой soak, max block time ≤ 50–55 % дедлайна, recovery после сбоев SD.

Панель/I-O:
- [ ] 16 энкодеров (2× MCP23017), 42 клавиши 6×7, экран 800×480, 10 джеков, 2 фейдера;
- [ ] CV out (MCP4728), CV in (MCP3208), gate; калибровка.

**Критерии выхода:** демо-трек 8 дорожек + 8 голосов, полный стенд панели.

## P5. Аналоговый тракт и EMC-прототип (параллельно P4)

- [ ] codec/CV/power mezzanine до основной платы: шум, USB/DSI bleed, защита CV IN,
      точность CV, нагрев в закрытом напечатанном корпусе;
- [ ] ±12 В для аналоговых картриджей (AS3340, LM13700, AS3320).

**Критерии выхода:** измеренный noise floor и отсутствие наводок от USB/дисплея.

## P6. Первая PCB под выбранный MCU (6–8 недель)

- [ ] CORE-1 (rev.1 этой архитектуры, не «rev.3»), PANEL-1, PWR-1;
- [ ] ERC 0, netlist-проверки, BOM, герберы; пробная партия 5 шт.

**Выход:** 3 платы, 5 собранных экземпляров.

## P7. MVP и пилот (12–18 недель)

- [ ] Sampler / Synth / Hybrid, общий секвенсор и 3D-мод-матрица; save/load;
- [ ] базовый SDK: статические C++-модули (audio-rate), Lua (control-rate);
- [ ] пилот 10–20 шт: сборка, гайд, обновление прошивки, manufacturing test, калибровка.

**Выход:** 10–20 работающих экземпляров, публичный релиз v1.0.

## P8. SDK сообщества (после стабильного ABI)

- [ ] SDK-документация и шаблоны; песочница Lua с лимитами; RP2350-картридж для
      недоверенного audio-rate кода (своя память, watchdog, TDM/I²S + SPI mailbox);
- [ ] аналоговые картриджи и сменные деки; каталог модулей; CI-проверки.

## Риски (сводно)

| Риск | Проявление | Смягчение |
|---|---|---|
| **Спека противоречива** | 4 ревизии панели, 3 габарита, 8↔16 энкодеров, 2.8″↔5″ | реестр `spec/90` + подписанный cut-list (P3) |
| **Недетерминированность общей памяти** | USB+SD+DSI+PSRAM одновременно → пропуски блоков | torture-test 24 ч (P2), max block time, а не средний CPU |
| **Разрастание DSP-спеки** | «insert»/ZDF/granular не определены → бюджет 51–109 % | workload freeze (P0), cost classes, admission control |
| **Аналог/EMC в плотном корпусе** | шум, наводки USB/DSI, нагрев | mezzanine до основной платы (P5) |
| Не хватит P4 | 8 стерео + 8 голосов + UAC2 | cut-list; H743 как альтернатива; voice expander по I²S |
| P4 молодой (preliminary) | SDK/кремний, джиттер кэша | H743 — контрольный кандидат; не фиксировать до P1–P2 |

## Критический путь

`P0 workload → P1 P4 vs H743 → P2 вертикальный spike → P3 cut-list/MCU → P4 ядро+панель → P6 PCB → P7 MVP/пилот → P8 SDK`.
`P5 (аналог/EMC)` идёт параллельно P4.
