# Софтовые модули и «машины» (загрузка по USB/Wi-Fi) — бэклог

Расширение концепции модульности: не только внешние аппаратные картриджи/деки, но и
**программные модули**: синтезаторы («машины»), эффекты, генераторы, плагины, которые
загружаются в Букифон по USB или Wi-Fi и работают внутри прошивки (или на companion-ПК).

## 1. Типы модулей

| Тип | Что | Куда загружается |
|---|---|---|
| **Machine** | полноценный синтезатор/сэмплер-движок (osc/filter/env/seq), занимает партию | P4, внутренняя flash/PSRAM |
| **Effect** | FX-модуль (delay/reverb/comp/bitcrush), в цепочку | P4 DSP |
| **Generator** | генеративный секвенсор/арп/евклид | seq engine |
| **Utility** | MIDI-процессор, CC-маппер, калибратор | USB/Wi-Fi, host |
| **Preset pack** | банк пресетов/сэмплов | SD/flash |
| **Companion** | редактор/менеджер библиотек на ПК/телефоне | USB/Wi-Fi (не на устройстве) |

## 2. Загрузка

- **USB Mass Storage / CDC**: копирование `.bkm` (Bukifon Module) на устройство; hot-plug.
- **Wi-Fi (C6)**: локальная веб-страница `http://bukifon.local/modules` (upload/install/manage)
  + опционально репозиторий (pull по HTTPS, подпись).
- **SD**: карта с `/modules/*.bkm` — офлайн-установка.
- Формат: zip/tar c `manifest.json` (SDK v3), DSP/бинарь, пресеты, LICENSE, sha256; подпись Ed25519.
- Совместимость: ABI major/minor, target (p4/s3/host), лимиты RAM/CPU, sandbox.

## 3. Архитектура (эскиз)

```
[.bkm] -> verifier (manifest, sha256, signature, ABI)
       -> installer (двухслотовая запись, recovery, rollback)
       -> module host (sandbox: MPU/PSRAM-arena, watchdog, лимит блоков)
       -> engine (machine/effect/generator)
```

- **Изоляция**: отдельная арена PSRAM, MPU-регионы, watchdog; аудио-колбэк с бюджетом (max block).
- **Ресурсы**: machine ≤ 8 МБ PSRAM/≤20 % CPU; effect ≤ 4 МБ/≤10 %; лимиты в манифесте.
- **Версии**: установка рядом (v1/v2), активная версия; downgrade/rollback.
- **Открытость**: SDK (C/C++), примеры (уже 2: tape delay, euclid arp), каталог сообщества.
- **Безопасность**: только подписанные модули (опция «developer mode»), никакой сети из модуля.

## 4. UX

- **Менеджер модулей** на устройстве: список, установка/удаление, версия, лицензия, ресурсы.
- **Web UI** (C6): drag&drop `.bkm`, прогресс, ошибки; офлайн-кэш.
- **Совместимость с пресетами**: при отсутствии модуля — предупреждение и «missing machine».
- **Экспорт проекта** с зависимостями (список модулей+версий) — воспроизводимость.

## 5. Этапы

| Версия | Что |
|---|---|
| v1.1 | `.bkm` формат, установка с SD, менеджер модулей, 2–3 примера |
| v1.2 | USB-установка (CDC/MSC), подпись Ed25519, sandbox MPU |
| v1.3 | Wi-Fi upload UI (C6), локальный каталог; репозиторий (опционально) |
| v2.0 | публичный SDK/каталог, machine-модули как продукт |

## 6. Ограничения/риски

- P4 RAM/CPU: machine-модули ограничены; тяжёлые — только как companion/плагин на ПК.
- Безопасность: сторонний код — sandbox/watchdog; подпись обязательна для «магазина».
- Лицензии: модули могут быть GPL/проприетарными — каталог с фильтром.
- Wi-Fi на C6: пропускная способность/латентность; аудио не стримим из сети.
- ABI нестабилен до v1.0 — публичный SDK после RC.

## 7. Связь с DAW-плагином

Софтовые модули и плагин используют один движок (C++), один формат пресетов (project v2),
один каталог. Плагин (VST3/AU/CLAP) может запускать те же machine-модули на ПК — см. docs/86.
