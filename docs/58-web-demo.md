# Веб-демо Букифона (интерактивная модель интерфейса)

Цель — дать будущему пользователю **потрогать интерфейс и звук до покупки/сборки**:
секвенсор, 16 энкодеров, 42 клавиши, фейдеры, джеки и 4 режима.

**Демо:** https://martiyanov.github.io/bukifon/demo/ (исходники — `docs/demo/`).
Запуск локально:

```bash
python3 -m http.server 8000 -d docs
# открыть http://localhost:8000/demo/
```

## Язык интерфейса (RU/EN)

Демо двуязычное, как прошивка ([docs/61](61-ui-design.md)): все видимые строки — кнопки,
чипы страниц, подписи параметров/макросов, контекст-строка, подсказки, статусы и UX-тест —
берутся из строковой таблицы `docs/demo/demo.js` (`I18N.ru` / `I18N.en`, 256 ключей) через
`t("key")`; «сырых» ключей в интерфейсе нет, у каждого ключа непустые RU и EN.

- **Переключатель:** `RU | EN` в шапке демо (кнопки с `aria-pressed`), язык применяется сразу.
- **URL:** `?lang=en` — английский интерфейс; без параметра — **RU по умолчанию**
  (пример: https://martiyanov.github.io/bukifon/demo/?lang=en).
- **Память:** выбор хранится в `localStorage` (`bukifon-demo-lang`) и применяется на следующем
  визите; при переключении параметр `?lang=` обновляется в адресной строке (`?test=1` и др.
  параметры сохраняются). Если EN пришёл из `localStorage`, при загрузке он тоже отражается
  в URL, чтобы ссылкой можно было поделиться.
- **Canvas:** подписи/статусы рисуются через `t()`; ширина каждой строки сверяется с шириной
  ячейки (аудит `window.__i18n.textFit(lang)`, лимит как у прошивки — docs/61), поэтому EN и RU
  строки не переполняют ячейки.

## Доступность

- у кнопок — видимая подпись + `aria-label`/`title`; у энкодеров и фейдеров —
  `role="slider"`, `tabindex="0"`, `aria-valuemin/max/now/valuetext`;
- клавиатура: стрелки — шаг (вверх/вправо = увеличить), `Shift` = шаг ×10, `PageUp/PageDown`
  = 10 %, `Home/End` = минимум/максимум; джеки — `role="button"`, `aria-pressed`, `Enter/Space`;
- видимый фокус — `:focus-visible` (2 px accent) у кнопок, ссылок, селектов, энкодеров,
  фейдеров и джеков; флеш-сообщения дублируются в скрытый `aria-live="polite"` регион;
- UX-тест (`?test=1`) не меняется: 8 задач, автоматический зачёт, COPY JSON.
- **Проверка:** `node tools/test_demo_ux.js` прогоняет UX-тест на **RU и EN** (8/8 задач,
  0 ошибок страницы), проверяет паритет ключей, ширину canvas-строк в ячейках и a11y
  (aria/роли/клавиатура/фокус). Можно гонять по одному: `node tools/test_demo_ux.js ru|en`.

| 10 джеков | клик — «воткнуть кабель» (визуально) |
| Режимы | SYNTH / SAMPLER / DAW / USB-KBD — разные экраны |
| Транспорт | PLAY/STOP, BPM, SPACE |
| Внешняя MIDI-клавиатура | Web MIDI, подключается автоматически |

## Раскладка

Демо повторяет **расположение** панели: 10 джеков сверху, 16 энкодеров (4×2 слева А–З и 4×2
справа И–П) вокруг экрана 800×480, два кластера клавиш 3×7 под ∓18°, фейдеры между ними.
Проверка топологии — `node tools/check_demo_layout.js`, результаты — [docs/67](67-panel-demo-layout.md).

## Звук

Упрощённый **2-оп FM** (WebAudio): 4 партии со своими настройками, 24 голоса max, ADSR,
lowpass-фильтр, delay, компрессор. Это не прошивка: реальный движок — 4-оп FM + wavetable +
SVF/ZDF на ESP32-P4, 8 стерео-дорожек, 32 МБ PSRAM.

## Ограничения демо (честно)

- сэмплер и DAW — схематичные экраны, без реального SD/CC;
- нет CV/GATE, модулей, сохранения проектов;
- звук упрощён; нет 8×8 USB-аудио;
- UI — веб-реплика по скриншотам из `firmware/artifacts/ui/`, а не сам firmware.
