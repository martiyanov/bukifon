# Второе мнение: MCU и архитектура для v1.0

Критика плана. Не спека. Оценки ±30 %, помечены как оценки; измеренные величины — со ссылкой.

## 1. Платформы: что решает

| | RP2040 | ESP32-S3 | ESP32-P4 | STM32H743 | Teensy 4.1 |
|---|---|---|---|---|---|
| Ядра | 2× M0+ 133 МГц | 2× LX7 240 МГц | 2× RV32 400 МГц | 1× M7 480 МГц | 1× M7 600 МГц |
| FPU | нет | float | float | float + double | float + double |
| SRAM | 264 КБ | 512 КБ | 768 КБ | 1024 КБ | 1024 КБ |
| Внешняя RAM | нет | 8 МБ PSRAM @80 МГц | 16/32 МБ @200 МГц | FMC SDRAM 16 бит | только пады FlexSPI2 |
| USB | FS 12 Мбит/с | FS 12 Мбит/с | **HS 480 Мбит/с** | HS 480 Мбит/с | HS 480 Мбит/с |
| 800×480 | SPI | SPI (10 МБ/с) | **DSI + PPA** | **LTDC + DMA2D** | SPI/FlexIO |
| GPIO | 26 | 45 | 55 | 114 | 55 |
| Цена 1k | $0.7 | $3–5 | $10–15 | $15–22 | $31 |

Три числа, которые отсекают варианты:

1. **USB.** 8 каналов out + 8 in, 48 кГц/24 бит = 16×3×48000 = **2.3 МБ/с = 18.4 Мбит/с**. У FS потолок ~9.8 Мбит/с (изохронные 90 % от 12). → UAC2 multichannel требует HS: P4 / H7 / Teensy. На S3 — максимум стерео 24/48 (2.3 Мбит/с) или 4 канала 16 бит в одну сторону.
2. **Экран.** Кадр 750 КБ. SPI 80 МГц = 10 МБ/с → **75 мс/кадр = 13 fps** на полную перерисовку. 30 fps — только если меняется <40 % пикселей (текст/бары — да, осциллограмма/волна — нет). DSI/LTDC рисуют сами, CPU 0 %.
3. **PSRAM.** Измерено на S3 (octal 80 МГц): **чтение 88 МБ/с, запись 49 МБ/с**, SRAM 425/760; flash и PSRAM делят MSPI и «ходят по очереди» ([benchmarks](https://github.com/tlack/babytalk/blob/25c9a73b1d54a48b649b781572ac37fdad761d80/docs/BENCHMARKS.md)). У P4 hex 200 МГц — на уровне DRAM ([WLED note](http://git.sebastienjean.net/jeans/WLED/commit/3c998110575a2ece3a7acaf0934cb4a5a6b2c768)).

## 2. Бюджет нагрузки (оценка)

| Блок | MMAC/s | Расчёт |
|---|---|---|
| Синт: 8 голосов × 4-op FM ×2 OS + ladder + 4 env | 55–80 | 8×4×2×48k×~6 MAC |
| Сэмплер: 8 стерео, 2 гранулы, SVF, 2 insert | 30–45 | без phase vocoder |
| То же 8 моно (Digitakt MKI) | 20–30 | вдвое меньше выборки |
| FX-шина, мастер, лимитер | 3–5 | |
| UI 800×480@30 | 15–30 % одного ядра | LVGL, частичная перерисовка |
| I/O: 16 энкодеров, 42 клавиши, 51 LED | 3–6 % | |

| Платформа | Эффективно MMAC/s | Синт + сэмплер стерео (90–125) | + UI | Итог |
|---|---|---|---|---|
| RP2040 | 60–90 (Q15) | 140–200 % | — | **не тянет** |
| S3 | 180–220 | 45–65 % | +10–20 % | **60–85 %, без запаса** |
| P4 | 300–350 | 27–40 % | +5–10 % | **35–50 %** |
| H743 | 280–320 | 30–42 % | +2 % | **35–45 %** |
| Teensy 4.1 | 350–400 | 25–35 % | +15–25 % (SPI/LVGL) | **45–60 %** |

Оценка калибруется по Октатреку: 8 стерео + 2 FX/дорожку он делал на DSP56300 ~100–150 MMAC/s. Значит 90–125 MMAC/s — правдоподобно; вопрос не в «FLOPs», а в том, что MCU ещё тянет UI, USB и память.

**Где реально упирается S3 — память, не арифметика:**

| | S3 | P4 | H7 |
|---|---|---|---|
| Потолок чтения | 88 МБ/с (изм.) | ~250–400 МБ/с | ~200 МБ/с (SDRAM) |
| 8 стерео-гранул, полезно | 12–25 МБ/с | 12–25 | 12–25 |
| С промахами кэша (×2–4) | 30–70 МБ/с | 30–70 | 25–50 |
| Дисплей 30 fps (30 % экрана) | 7 МБ/с | PPA/DSI | LTDC сам |
| **Итого** | **40–80 из 88** | 40–80 из 300 | 40–70 из 200 |
| Запас | нет | 3–5× | 2–3× |

Причина усиления: гранулярное чтение прыгает по памяти, 64-байтная линия кэша отдаёт 8–16 полезных 16-битных сэмплов, а аудиокод ещё и XIP-ится из того же MSPI.

## 3. Минимум для «сэмплер + синтез одновременно», предел, что резать

**Минимальный набор (P4):** модуль P4 16 МБ PSRAM (32 лучше), PCM5102A + PCM1808, 2× MCP4728, MCP3208, SD по SDIO 4 бита, 5″ DSI 800×480, 2× MCP23017 на 16 энкодеров, матрица 6×7 на 42 клавиши + 74HC165, WS2812 через RMT, MIDI TRS, 3.3 В/1.5 А.

**Бюджет PSRAM 32 МБ:** сэмплы 16 МБ, UI 2×750 КБ, FX-линии 1 МБ, таблицы 0.5 МБ, код/heap 2 МБ → влезает. В 8 МБ S3: 8 дорожек × ~4 с стерео 48k/16 бит — это не сэмплер, а демо.

**Предел:** 8 стерео × 30 с = 46 МБ (не влезает даже в 32 МБ); 8 голосов + 8 дорожек + 2 insert ≈ 45–50 % P4. Дальше упирается не в ядра, а в FX (каждый insert ~2–3 % P4), дисплей и USB.

**Резать в этом порядке:**
1. 8 стерео → **8 моно** (вдвое меньше память и шина; ровно как Digitakt MKI — он моно, стерео появилось только в Digitakt II).
2. 2 insert FX → **1 insert + 2 send** (как у Digitakt: filter + drive + send на delay/reverb, а не два полных insert).
3. Time-stretch — **только гранулярный**. Phase vocoder на 8 стерео = 300–500 MFLOP/s и +8–12 недель разработки; у Elektron он тоже «характерный», а не эталонный.
4. 48 → 44.1 кГц даёт всего 8 %, не тратить на это решение.
5. Голоса 8 → 6 — последний резерв, не первый.

## 4. Второй чип / DSP / FPGA

| Вариант | Цена | Что даёт | Чего не может | Труд | Вердикт |
|---|---|---|---|---|---|
| ADAU1701 | $6–9 | 1024 инстр/сэмпл, FX/микшер, I2S | нет памяти сэмплов, фикс-точка, нет FM | 3–4 нед | не нужен |
| ADAU1467 | $12–25 | 294 МГц, 320 КБ RAM | нет внешней памяти, SigmaStudio | 6–10 нед | не нужен |
| SHARC ADSP-21569 | $25–35 | DDR3L, как в Digitakt II | CCES, 9–12 мес | 9–12 мес | только если цель — буквально повторить Elektron |
| Spartan-7 | $30–40 | I/O, TDM, таймеры | DSP-разработка медленная | 2–3 мес (I/O) | только глю, не DSP |
| RP2040 как I/O-сопроцессор | $0.7 | 51 LED, 16 энкодеров, клавиши, PIO | аудио не тянет | 2 нед | опционально |

ADC/DAC уже внешние. Второй чип добавляет вторую тулчейн-цепочку, загрузку, линк параметров и ещё одну точку отказа — за выигрыш 15–25 % загрузки. Если P4 не хватит, дешевле добавить **второй P4/RP2350 как voice expander по I2S**, чем SigmaDSP: тот же код, тот же тулчейн.

FPGA имеет смысл только если понадобится 8+ каналов TDM, точные CV-таймеры или свой протокол шины. У Elektron FPGA — обвязка и управление аналогом, не DSP.

## 5. Пользовательские DSP-модули: sandbox

| Формат | Скорость | Безопасность | Когда |
|---|---|---|---|
| Статический C++ (сборка прошивки) | 1.0× | 5/5 | аудио-рейт, v1.0 |
| .bin по фиксированному адресу | 1.0× | 1/5 | только свои, с safe-mode |
| WASM-интерпретатор | 0.05–0.1× | 4/5 | не для аудио |
| WASM AOT | 0.5–0.8× | 4/5 | риск тулчейна под Xtensa/RV32 |
| Lua | 0.001–0.01× | 5/5 | control-rate 1 кГц, UI, секвенсор |
| Свой MCU в картридже | 1.0× | 5/5 (изоляция) | community-модули, +$1–3 |

Ключевое: у S3/P4 **нет MMU**, у S3 нет и пользовательского MPU; «.so» и фикс-адресные бинарники — это не sandbox, а доверие. Реалистичная схема — три уровня: аудио-рейт статически в прошивке (source-only, community PR), control-rate Lua/WASM с бюджетом инструкций, аппаратная изоляция в картридже.

Подводные камни, каждый стоит xrun:
- DMA-буфер только во внутренней RAM, выравнивание 32/64 Б, `esp_cache_msync`; указатель в PSRAM в I2S DMA → мусор и щелчки.
- Код модуля не в PSRAM/flash XIP: промах в аудио-блоке = джиттер. Аудио-функции в IRAM.
- Запрет длинных ISR: блок 64 сэмпла = 1.33 мс; модуль не должен занимать больше ~40–60 мкс.
- `malloc/new` в `process()` запрещены, пул на старте, иначе фрагментация за час.
- Денормалы/NaN: FTZ + проверка раз в блок, иначе провал на 20 дБ и клип.
- Watchdog по циклобюджету: 2 блока подряд сверх → bypass модуля.
- ABI/версия/CRC: .bin от прошлой прошивки = кирпич; safe-mode по удержанию кнопки.
- Стек 4–8 КБ на модуль, отдельная задача на core0, никогда в ISR.

## 6. Дорожная карта: что не так и как надо

Что не так в предложенном порядке:
- **rev.3 до firmware MVP** — фиксируем плату, не зная бюджета памяти/CPU. Ошибка стоит 3–4 недели и ~$300 за респин.
- **module SDK до производства** — SDK без пользователей; на v1.0 он не влияет.
- **«производство»** для открытого 3D-печатного проекта — это пилот 10–20 шт, не серия.

| Этап | Нед. | Критерий выхода (числа) |
|---|---|---|
| 0. Бенчмарк кремния | 2 | 3 devkit (P4/S3/H7); отчёт: xruns/час, CPU %, PSRAM МБ/с, fps, latency |
| 1. Freeze требований | 2 | одна спека: 16 энк/5″/380×210×63/8 stereo/8 voices/USB HS; cut-list подписана |
| 2. Аудио-ядро на devkit | 8–10 | 8 stereo + 8 voices, 48k/64, **0 xruns/час**, CPU ≤70 %, latency ≤6 мс |
| 3. Панель/IO на devkit | 4 | 16 энкодеров без пропусков @300 rpm, 42 клавиши, 51 LED@60 fps, UI 30 fps |
| 4. Rev.3 | 6–8 | DRC/ERC, 3 платы, bring-up-чеклист, шум ≤ −85 dBu, ток по рельсам в бюджете |
| 5. Firmware MVP | 10–12 | все режимы, 1 ч soak, 0 xruns, патчи/plocks сохраняются |
| 6. Пилот 10–20 шт | 4–6 | сборка ≤4 ч/шт, yield ≥80 %, цена ≤ BOM×1.6 |
| 7. Module SDK | после | 3 примера, ABI v1, safe-mode |

Порядок: 0 → 1 → (2 ∥ 3) → 4 → 5 → 6 → 7. Этапы 2 и 3 идут параллельно на devkit, до разводки.

Протокол бенчмарка (обязателен до выбора чипа): 8 стерео-гранул + 8 голосов при 48k/64; час; счётчик xruns; замер PSRAM именно гранулярным чтением (не memcpy); 800×480 при 30 fps с полной волной; UAC2 8×8 каналов.

## 7. Три главных риска

1. **Спека, а не кремний.** Четыре ревизии панели, три габарита, 8↔16 энкодеров, 2.8″↔5″, 30↔60 мм фейдеры, 4 части↔8 дорожек. Снимать: реестр требований с ID, доска изменений, cut-list, подписанный до rev.3.
2. **Память/шина.** PSRAM + кэш + фреймбуфер + USB на одном MSPI. Снимать: бенчмарк на реальной гранулярной нагрузке, требование запаса 2×, дисплей на отдельной шине (DSI/LTDC), аудио в SRAM.
3. **Аналог/механика.** 42 клавиши + 16 энкодеров + 5″ + 10 джеков в 63 мм, ±12 В модули, AS3320 DIP-18. Снимать: плоский прототип на стенде, замер шума/наводок/посадки до корпуса.

## Вердикт

1. **ESP32-P4** — единственный кандидат, который тянет 8 стерео + 8 голосов + 800×480 + UAC2 с запасом 2–3×; USB HS и DSI решают оба упора.
2. **ESP32-S3** — только с урезанием до 8 моно, 6 голосов, SPI-экрана с частичной перерисовкой и USB-стерео; 8 стерео и UAC2 на нём не выйдут.
3. **RP2040** — оставить как I/O-сопроцессор (LED/энкодеры/клавиши), не как аудио-движок; RP2350 — промежуточный апгрейд без смены форм-фактора.
4. **DSP/FPGA в v1 не брать**: ADAU1701/1467 не играют сэмплы, SHARC — это 9–12 месяцев и другая лицензионная модель.
5. Первый шаг — не rev.3, а 2 недели бенчмарка на P4/S3/H7 и сведение трёх спек в одну.
