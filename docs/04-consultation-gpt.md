# Консультация GPT (Codex, gpt-5.6) по MCU и архитектуре

Получена 05.11.2025 через Codex CLI (модель `gpt-5.6-sol`, fast). Это независимое мнение
по тем же вопросам, что разобраны в `docs/03-second-opinion-mcu.md` (DeepSeek) и
`docs/11-esp32-feasibility.md`. Ниже — ответ без пересказа, с поправками к нашему плану.

## 1. Платформа

| Вариант | Сильная сторона | Критическое ограничение | Вердикт |
|---|---|---|---|
| **ESP32-P4, 32 МБ** | 2×400 МГц, HS USB с PHY, DSI/PPA, 16-битная DDR PSRAM | молодой SDK/кремний, кэш и PSRAM дают джиттер; даташит preliminary | основной кандидат |
| **STM32H743 + SDRAM** | зрелый Cortex-M7/DSP, TCM 192 КБ, LTDC + DMA2D, предсказуемый real-time | один core; для USB HS нужен внешний ULPI PHY | обязательный контрольный кандидат |
| Teensy 4.1 | M7 600 МГц, зрелое аудио | плохой финальный модуль, нет LTDC/DSI | только стенд/референс DSP |
| ESP32-S3 | дешёвый и зрелый | FS USB, слабее память/CPU | **исключить** при 8×8 UAC2 |

Поправка к нашему P1: S3 не проходит не «с запасом», а аналитически — 8 каналов × 24 бит ×
48 кГц = **9.216 Мбит/с в каждом направлении**, это больше предела одного FS isochronous
endpoint (90 % от 12 Мбит/с). Сравнивать надо **P4 и H743**, Teensy — только как стенд.
Источники: [ESP32-P4 datasheet](https://documentation.espressif.com/esp32-p4_datasheet_en.html),
[STM32H743](https://www.st.com/en/microcontrollers-microprocessors/stm32h743-753.html).

## 2. Тянет ли P4 заявленное

Вердикт: **урезанный набор правдоподобен, но «запас 2×» пока не доказан.**

Дедлайн блока 64 сэмпла при 48 кГц — **1.333 мс**. Ориентировочный бюджет полного режима:

| Нагрузка | Оценка P4 |
|---|---:|
| 8 mono granular-дорожек (интерполяция, фильтр, огибающие) | 12–22 % |
| 8 голосов: 4-оп FM/wavetable + один ZDF-фильтр | 18–35 % |
| 1 insert на дорожку | 8–20 % |
| 2 send + master | 5–10 % |
| секвенсор, UAC2, SD, MIDI | 5–12 % |
| UI через DSI/PPA | 3–10 % (конкурирует за память) |
| **Итого** | **51–109 %** |

Разброс большой, потому что «insert», ZDF и granular не определены алгоритмически:
один нелинейный ZDF с 2–4 итерациями может стоить дороже всей FM-части.

**Правильный критерий — не средний CPU, а `max block time ≤ 0.65 мс` при дедлайне
1.333 мс** и отсутствие xruns 8–24 часа. «CPU ≤ 70 %» цели «запас 2×» не соответствует:
запас 2× — это **≤ 50 % worst-case**.

Память (важное уточнение):

- 8 mono × 30 с × 48 кГц × 16 бит = **23.0 МБ**;
- два RGB565-фреймбуфера = **1.54 МБ**;
- остаётся ~7 МБ на FX/heap/таблицы → **32 МБ PSRAM обязательны**, 16 МБ мало;
- длинные сэмплы — стримить с SD/eMMC, не держать в RAM.

UAC2 8×8/24/48 в TinyUSB на P4 есть, но проверять надо **вместе** с SD, DSI и аудио.
Источники: [P4 USB stack](https://docs.espressif.com/projects/esp-idf/en/latest/esp32p4/api-reference/peripherals/usb_device.html),
[Espressif UAC2](https://docs.espressif.com/projects/esp-iot-solution/en/latest/usb/usb_device/usb_device_uac.html).

## 3. Что резать (приоритет отличается от нашего)

1. **Сложность insert-FX, а не число дорожек.** Фиксированный каталог: EQ/SVF, drive,
   bitcrusher, chorus; convolution/spectral/тяжёлый pitch — только send или offline.
2. **Одновременный stretch:** granular доступен всем 8 дорожкам, качественный режим —
   например, 4 дорожкам; нужен admission control по CPU.
3. **ZDF:** один фильтр на голос, фиксированное число итераций; второй/нелинейный —
   quality mode с уменьшением полифонии.
4. Потом голоса **8 → 6**.
5. Дорожки 8 → 6 — только последним.

Stereo → mono даёт ×2 по памяти и чтению, но **не** ×2 по CPU (секвенсор, огибающие,
анализ stretch и часть FX остаются).

## 4. Второй DSP и модули

- **ADAU1467 в v1 не нужен:** годится как mixer/send/master, но не решает sample memory,
  granular stretch, FM и пользовательский DSP; +toolchain и маршрутизация.
- **SHARC в v1 не нужен:** только если бенчмарк P4 провален или spectral stretch станет
  обязательным. На PCB заложить TDM/I²S expansion header.
- **Lua — не песочница:** аудио-рейт — статический проверенный C++; Lua/WASM — control-rate
  (лимит инструкций/памяти/времени); watchdog: превышение бюджета двух блоков подряд →
  bypass; запрет allocation/locks/fs/callbacks в `process()`; CRC/ABI + safe mode.
- Для недоверенного audio-rate кода лучший вариант — **RP2350 в картридже** (своя память,
  watchdog, физическая граница отказа). Интерфейс — **TDM/I²S + SPI mailbox**; текущей
  аналоговой 26-pin шины для цифрового модуля **недостаточно**.

## 5. Дорожная карта (исправленная)

| Этап | Срок | Выход |
|---|---:|---|
| P0. Заморозить benchmark workload | 1 нед | точные FX, ZDF, stretch, длина сэмплов, UAC-конфигурация |
| P1. P4 против H743 | 2–3 нед | granular random-read, DSP-ядра, USB 8×8 |
| P2. Вертикальный spike | 3–4 нед | одновременно audio + SD + UI + UAC2 |
| P3. Requirements/cut-list | 1 нед | выбор MCU и quality tiers |
| P4. Аудиоядро и панель параллельно | 8–12 нед | 24-часовой soak, max block time ≤ 50–55 % дедлайна |
| P5. Аналоговый тракт + pre-layout прототип | параллельно | шум, clock bleed, точность CV, питание |
| P6. Первая PCB под P4/H7 | 6–8 нед | не называть rev.3 без rev.1/2 этой архитектуры |
| P7. MVP и пилот | 12–18 нед | recovery, update, калибровка, manufacturing test |
| P8. SDK | после стабильного ABI | минимум три реальных модуля |

Главная ошибка нашего плана: P3 проверял аудиоядро **без полного конфликта ресурсов**.
Устройство падает не на изолированном DSP, а при USB + SD + DSI + PSRAM одновременно.

## 6. Три главных риска

1. **Недетерминированность общей памяти** — torture-test: DSI-перерисовка волны +
   worst-case SD + USB 8×8 + random granular reads; логировать максимум времени блока.
2. **Разрастание DSP-спеки** — cost classes и ресурсный планировщик: патч не может
   активировать конфигурацию дороже 50–55 % измеренного бюджета.
3. **Аналог, питание, EMC в плотном корпусе** — до основной PCB собрать codec/CV/power
   mezzanine: шум, USB/DSI bleed, защита CV IN, нагрев в закрытом корпусе.

## 7. Вердикт GPT (5 строк)

1. ESP32-P4 32 МБ — разумный фаворит, но **кандидат, а не доказанная платформа**.
2. 8 mono + 8 голосов он, вероятно, потянет; максимум ZDF/stretch/FX одновременно —
   без вертикального бенчмарка не гарантируется.
3. Запас 2× = **≤ 50 % worst-case дедлайна**; критерий «CPU ≤ 70 %» этому противоречит.
4. ADAU/SHARC в v1 не ставить; для недоверенного audio-rate — RP2350-картридж,
   цифровой expansion-интерфейс (TDM/I²S + SPI).
5. Первым делать 3–4-недельный spike **P4 против H743** со всеми четырьмя конкурентами:
   DSP, PSRAM/SD, DSI, UAC2.
